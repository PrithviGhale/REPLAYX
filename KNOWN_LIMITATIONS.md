# Known limitations — 0.1.3-alpha.1

This is an alpha undergoing beta hardening. See [VALIDATION.md](VALIDATION.md) for actual evidence and [PERFORMANCE.md](PERFORMANCE.md) for measurement limits.

- **The audio crackle fix still needs a listening test.** Objective measurements on real capture (VALIDATION.md) show the discontinuities are gone, but nobody has listened to a comparison yet. Procedure: start REPLAYX 0.1.3, enable replay with System audio, play music or a video with speech for at least 60 seconds, save a replay, then play the clip in VLC or Windows Media Player on headphones and listen for clicks, crackle or roughness compared with the original. Note the Performance page's *Audio discontinuities* value before stopping.
- **Do not use or distribute the 0.1.2-alpha.1 or 0.1.0 installers**; they contain the crackling-audio defect.
- Microphones remain unverified for speech. The built-in Realtek Microphone Array reports 4 channels with no channel mask; Windows performs its stereo conversion and the result has not been listened to.
- A direct FFmpeg native-AAC 192k encode of the synthetic test tone (without REPLAYX) showed phase artifacts on one channel. REPLAYX clips did not, but the encoder's behaviour on varied real content is uncharacterised.
- *Audio discontinuities* counts timeline re-anchors where audio arrived late after a stall, gross timestamp jumps, and Windows-flagged device glitches. It does not count codec artifacts. Drift correction (at most +/-0.5%) is designed to be inaudible, but long real sessions are untested.

- The previous development FFmpeg build was quarantined by Defender. It has been replaced by a checksum-pinned stable-branch LGPL build; a custom Defender scan found no threats and the new runtime launches with protection enabled. This does not establish the safety of every future update. See the latest validation record.
- Fullscreen Valorant at 1280 x 960 / 1440 x 1080 remains unverified under both Windows and NVIDIA mode changes. Geometry checks, manual crop and 1920 x 1080 stretch are implemented. The engine cannot infer a game subregion inside a full-resolution desktop or every driver letterboxing case. The user confirmed fullscreen; GPU versus display scaling remains unknown.
- The earlier GPU scaler failed with texture error 80070057. CPU scaling plus NVENC worked previously. Current GPU success and zero-copy operation are not established.
- Display recovery is implemented but physically untested. It splits recording parts, resets replay and quarantines the last completed/in-flight segments, deliberately excluding uncertain footage. Polling cannot detect driver changes invisible to Windows geometry. Inspect retained quarantine data only after capture stops.
- DXGI outputs on the default adapter are supported. Rotated outputs fail explicitly. Windows Graphics Capture, HDR tone mapping, arbitrary monitor subsets, protected surfaces, secure desktops and anti-cheat/DRM bypass are unavailable. GDI all-desktop includes the entire virtual desktop.
- Intelligible microphone speech, independent Discord/game tracks, editor multitrack playback and long-session real-device sync are unverified. Earlier microphone packets had zero peak. Synthetic separation/sync tests do not prove these cases.
- Device selection exists; automatic device switching does not. Stop, refresh devices, reselect, save and restart after changes. Process restart requires re-selection. Microphone monitoring and recording pause are unavailable.
- Replay uses complete two-second segments and can end about two seconds before save or include an extra segment. Saving keeps buffering. Stopping a full recording briefly restarts replay.
- Full recordings, pending snapshots, old sessions and quarantine use disk beyond the active ring budget. Disk-reserve tests are policy tests, not a physically full-volume test. Recovery excludes quarantine and unreadable media.
- Windows job cleanup and data-directory instance locking are implemented. A brief spawn-to-job-assignment interval remains. Actual encoder/app crashes, GPU reset, device unplug and sleep/resume during capture are unverified.
- Per-segment probing and full-decode verification can make long/concurrent saves expensive. No real 30-minute soak, current gameplay benchmark, GPU utilization or per-frame latency measurement is available. Earlier CLI CPU/memory zeros were uninstrumented. GUI totals now include all descendant processes.
- Clips open in the default player. In-app playback/editing, thumbnails, trimming, startup launch and persistent diagnostic logging are unavailable. 4K is experimental; HEVC/AV1 are unavailable.
- Installer state is recorded in VALIDATION.md; earlier installers predate the audio fix. Installation, installed recording, upgrade/uninstall and Authenticode signing are unverified. No new installer was made while the runtime remained blocked.
- Updates remain disabled without an endpoint and public signing key. Signed update installation/rollback is untested. Hosted CI has been configured but not run.
- Local PCM uses unauthenticated loopback TCP. Peer authentication, exact corresponding FFmpeg/dependency source packaging, complete license review and an immutable media archive are public-release gates.
