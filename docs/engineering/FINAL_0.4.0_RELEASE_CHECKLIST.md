## Signing inputs

- **Windows Authenticode.** If you already have a trusted signing certificate, authorize access on the signing runner and provide its thumbprint, RFC 3161 timestamp URL and SignTool path. The certificate must have the Code Signing EKU and an accessible key. The existing build script accepts these options. If you need a signing service and are eligible, Microsoft Artifact Signing **Basic Public Trust** is listed at $9.99 USD/month. It needs a paid Azure subscription, verified identity, an account endpoint, signing-account name, certificate-profile name, and an authorized signer with the Certificate Profile Signer role. Individual enrollment is available in the US and Canada. An individual-validation certificate with its provider's token or cloud signing is an alternative. Provide non-secret metadata and authorize the signer. Keep private credentials and identity documents with the provider. [Microsoft eligibility](https://learn.microsoft.com/en-us/azure/artifact-signing/quickstart) · [Basic pricing](https://learn.microsoft.com/en-us/azure/artifact-signing/how-to-change-sku) · [Signing integration](https://learn.microsoft.com/en-us/azure/artifact-signing/how-to-signing-integrations) · [Individual certificate example](https://www.ssl.com/products/software-integrity/code-signing/iv/)
- **Tauri updater.** Reuse the key whose public half is in the published builds. There is no purchase. Confirm access to the existing key and password through the approved signing runner or the repository secrets TAURI_SIGNING_PRIVATE_KEY and TAURI_SIGNING_PRIVATE_KEY_PASSWORD. The documented local key and password files were found by existence check. The published Alpha.9 signature verified against the current embedded public key and the hash-matched Alpha.9 installer. Their values, usability and CI availability remain to be checked on that runner. Sign the final Authenticode-signed installer and verify it against the embedded public key for 0.4.0. [Tauri updater signing](https://v2.tauri.app/plugin/updater/#signing-updates)
- **Release bytes.** Use the same installer for QA, both signatures, checksums and the final download. The current release workflow enables the Tauri signature. Use the Windows signing runner for Authenticode or wire the selected provider into the release workflow before relying on it for a Windows-signed release. Verify Windows signatures and timestamps with SignTool, validate the updater signature and check that latest.json points to the final archive's exact release and version. The published Alpha.9 FFmpeg source asset matches the unchanged runtime pin and previously recorded SHA-256. Reuse that archive and validate its hash on the draft. Set every release version to 0.4.0 before building and signing the stable package. Keep any signing secrets out of chat and artifacts.
- **Updater timing.** The production updater discovers published GitHub releases. The loopback test feed is development-only and prevents installation. Before publication, use offline signature validation plus the signed manual-install matrix. Immediately after approved publication, test **Settings → Updates → Check Now** from an isolated Alpha.9 installation against the stable release. Confirm both restart and data retention. If a full pre-public production-like updater drill is required, it needs a separately approved staging baseline and feed.

## Real-device AAC result

The approved 18-second capture ran on November 19, 2026. The isolated diagnostic attached recording and Instant Replay to the same FFmpeg capture session without opening the installed app profile. The built-in 2560 ? 1600, 60 Hz Intel display was captured through Desktop Duplication, with hardware H.264 Quick Sync scaling and encoding at 1920 ? 1080, 60 FPS. Windows routed system audio through its default FxSound playback endpoint. No microphone was opened.

Both files independently decoded all 1,080 video frames and both AAC streams. Video intervals were 16?17 ms with keyframes every two seconds. On each track, all AAC packet intervals were 21?22 ms across the entire clip, including segment joins. The largest decoded audio timestamp gap was 0.667 ms, within Matroska rounding. The prior recurring 16/17/33/34 ms audio packet pattern was absent. The engine reported zero audio gaps, discontinuities, and recovery sessions.

Each clip had 12 matched flash/beep pairs. The measured beep offsets were ?15 to +2 ms, with the same early and late mean of ?6.5 ms. The fixture detector's offline bias was ?2 ms. Both files carry a Playback mix and a System audio stream. Their decoded contents match because the same system source was the only input. Independent multi-input audio still has the earlier generated coverage. The recording and replay became playable in 1.947 and 1.941 seconds.

The clips, decoded A/V report and encoded packet report are in test-output/rc3-real-ffmpeg-av-20261119-092048. The diagnostic-only with_replay=1 option attaches recording to the running replay path. To reproduce this approved test in a separate folder, use record-test 18 system fps=60 width=1920 height=1080 codec=h264 engine=ffmpeg capture_api=dda with_replay=1. Play the quiet 12-second fixture only after the recorder reports frames. Leave Windows device selection and volume unchanged.

Use the [installer scenarios](INSTALLER_QUALIFICATION.md) for settings and data preservation. The cloud-qualified installer, the original staged installer and the verified optical image each have their own recorded checksum. An unsigned-package manifest dry run emitted no updater manifest, as intended. The remaining pre-publication work is the exact signed stable installer, its manifest and the disposable install, upgrade and uninstall checks.
